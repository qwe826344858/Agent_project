## 五、核心问题与优化建议

### 问题 P1：关键词提取/意图映射偏差（影响：高）

**现象**：家庭主妇问"全家保险规划"，返回旅游保险、自驾游保险、亚马逊商业责任险；宝妈问"宝宝保险"，混入车类运动保险和境外留学意外险。

**根因**：`platform_apis/base.py` 的 `KEYWORD_MAPPING` 关键词映射不够精准。"全家保险"可能被拆解为泛化关键词，导致平台 API 搜索到无关品类。

**建议**：
1. 在 LLM 意图识别阶段提取结构化查询词（险种 + 人群 + 场景），而非直接用原文搜索
2. 增加搜索结果的**品类过滤**：当用户意图为"重疾/医疗/意外"时，过滤掉旅游险、财产险、责任险等无关品类
3. 在 `KEYWORD_MAPPING` 中增加更精确的映射：`"全家" → "家庭保险"`、`"宝宝" → "少儿医疗险"`

### 问题 P2：预算筛选对低预算场景失效（影响：中）

**现象**：应届生预算 500 元，但返回的产品包含 0.2 元/起的交通意外险；家庭主妇预算 1 万，返回了 1 元的旅游险。

**根因**：预算筛选的 50% 容差在低价产品上过于宽松（500 × 50% = 250，0.2 元的产品远低于下限但仍被保留）。

**建议**：
1. 增加**最低价格门槛**过滤：如产品价格 < 预算的 10%，视为不相关
2. 考虑按"保障充足度"排序而非仅按价格接近度

### 问题 P3：小雨伞 company 字段缺失（影响：低）

**现象**：小雨伞平台返回的产品 `company` 为空字符串。

**建议**：在 `xiaoyusan.py` 解析时从产品名中提取保险公司（如"众安保险众民保" → company: "众安保险"）。

### 问题 P4：响应耗时偏长（影响：中）

**现象**：平均 18.9s，主要瓶颈在 LLM 生成（12-15s）。

**建议**：
1. 利用双通道优势——产品卡片已在 3-5s 内展示，文字建议流式输出用户可同步阅读
2. 考虑 LLM 响应精简化（当前 434-846 字，可引导 Prompt 控制在 300 字以内）
3. 前端已实现流式渲染，实际体感优于总耗时数字

## 七、结论

SmartInsure Agent 在**文字建议质量**和**意图识别**方面表现优秀（特别是高中生科普场景满分），SSE 事件流、Markdown 格式、来源/免责声明等**功能完整性**无可挑剔。

主要短板集中在**产品推荐精准度**和**预算匹配度**，尤其在复合意图（"全家规划"）和特定人群（"宝宝"）场景下，关键词映射不准导致推荐结果严重偏离用户需求。

**优先修复项**：P1（关键词/意图映射优化）→ P2（预算过滤增强）→ P4（响应速度优化）
