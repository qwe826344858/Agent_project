# 文本流式渲染优化方案

状态：待评审
关联：阶段一 MVP `前端专题/06-产品推荐双通道方案-前端.md`

## 一、现状分析

### 1.1 当前实现

| 维度 | 现状 | 问题 |
|---|---|---|
| 文本渲染 | `<p>` + `whitespace-pre-wrap` 纯文本输出 | 不支持 Markdown，列表/加粗/标题等格式丢失 |
| 流式效果 | `content + data.text` 逐字拼接 | 文字瞬间出现，无视觉过渡，体感生硬 |
| 光标动效 | `animate-pulse` 脉冲竖线 | 仅透明度变化，辨识度低 |
| 代码块 | 不支持 | LLM 偶尔输出对比表格或条款引用，无法格式化 |

### 1.2 目标效果

- LLM 输出的 Markdown 格式（加粗、列表、标题、表格）正确渲染
- 流式输出有"打字机"视觉节奏感
- 光标清晰可见，随文本尾部移动
- 代码块/引用块有区分背景色

## 二、方案设计

### 2.1 引入 Markdown 渲染

**新增依赖**：`react-markdown` + `remark-gfm`（支持表格、删除线、任务列表）

```
npm install react-markdown remark-gfm
```

**渲染组件封装**：新建 `src/components/MarkdownRenderer.tsx`

```typescript
import ReactMarkdown from 'react-markdown';
import remarkGfm from 'remark-gfm';

interface Props {
    content: string;
    isStreaming?: boolean;
}

export default function MarkdownRenderer({ content, isStreaming }: Props) {
    return (
        <div className="markdown-body">
            <ReactMarkdown remarkPlugins={[remarkGfm]}>
                {content}
            </ReactMarkdown>
            {isStreaming && <StreamingCursor />}
        </div>
    );
}
```

**Markdown 样式**：在 `globals.css` 中增加 `.markdown-body` 样式规则（覆盖 Tailwind reset）：

### 2.2 流式光标升级

**替换现有** `animate-pulse` 竖线，改为闪烁方块光标（更接近终端/ChatGPT 体感）：

```css
@keyframes cursor-blink {
    0%, 100% { opacity: 1; }
    50% { opacity: 0; }
}
.streaming-cursor {
    display: inline-block;
    width: 0.5em;
    height: 1.1em;
    background-color: #3b82f6;
    border-radius: 1px;
    vertical-align: text-bottom;
    margin-left: 2px;
    animation: cursor-blink 1s step-end infinite;
}
```

**组件**：

```typescript
function StreamingCursor() {
    return <span className="streaming-cursor" aria-label="正在输入" />;
}
```

### 2.3 逐段淡入动效

当 Markdown 渲染产生新的块级元素（段落、列表项）时，使用 CSS 动画让新内容"淡入上滑"：

```css
@keyframes fade-in-up {
    from { opacity: 0; transform: translateY(6px); }
    to   { opacity: 1; transform: translateY(0); }
}
.markdown-body > *:last-child {
    animation: fade-in-up 0.3s ease-out;
}
```

> **性能说明**：仅对最后一个子元素应用动画（`:last-child`），不会导致全量重绘。`transform` 和 `opacity` 属性由 GPU 合成层处理，不触发 layout reflow。

### 2.4 自动滚动优化

当前使用 `scrollIntoView({ behavior: "smooth" })`，在快速流式输出时可能造成滚动抖动。

**优化策略**：

```typescript
// 节流滚动：每 100ms 最多触发一次
const scrollThrottleRef = useRef<number>(0);

const scrollToBottom = useCallback(() => {
    const now = Date.now();
    if (now - scrollThrottleRef.current < 100) return;
    scrollThrottleRef.current = now;
    bottomRef.current?.scrollIntoView({ behavior: "smooth" });
}, []);
```

增加"用户手动上滚后暂停自动滚动"逻辑：

```typescript
const [userScrolled, setUserScrolled] = useState(false);

// 监听滚动事件
const handleScroll = useCallback((e: React.UIEvent) => {
    const el = e.currentTarget;
    const atBottom = el.scrollHeight - el.scrollTop - el.clientHeight < 80;
    setUserScrolled(!atBottom);
}, []);

// 仅在未手动上滚时自动滚动
useEffect(() => {
    if (!userScrolled) scrollToBottom();
}, [messages, userScrolled]);
```

## 三、ChatMessageList 变更

### 3.1 AssistantBubble 渲染变更

**变更前**：
```tsx
<p className="whitespace-pre-wrap break-words text-gray-800">
    {message.content}
    {message.isStreaming && <span className="animate-pulse">|</span>}
</p>
```

**变更后**：
```tsx
<MarkdownRenderer
    content={message.content}
    isStreaming={message.isStreaming}
/>
```

### 3.2 消息气泡宽度调整

Markdown 表格可能较宽，助手消息气泡宽度从 `max-w-[80%]` 调整为 `max-w-[85%]`，并增加水平溢出滚动：

```tsx
<div className="max-w-[85%] overflow-x-auto">
```

## 五、新增依赖

| 包名 | 版本 | 大小(gzip) | 用途 |
|---|---|---|---|
| `react-markdown` | ^9.x | ~8KB | Markdown → React 组件 |

> 总增量 ~10KB gzip，对首屏加载影响可忽略。

## 六、验收标准

| 项目 | 标准 |
|---|---|
| Markdown 渲染 | LLM 输出的 `**加粗**`、`- 列表`、`> 引用`、表格正确渲染 |
| 流式光标 | 蓝色方块光标在文字末尾闪烁，流式结束后消失 |
| 逐段淡入 | 新段落/列表项出现时有 0.3s 淡入上滑动效 |
| 自动滚动 | 流式输出时自动跟随，用户手动上滚后暂停，滚到底部恢复 |
| 移动端 | 表格水平可滚动，不破坏页面布局 |
| 性能 | 连续 50 条 delta 事件渲染无卡顿（Chrome DevTools Performance 面板无长任务 >50ms） |
