# 上线与复盘

状态：已完成

## 一、文档目标

本文件用于规范阶段一（MVP）上线流程与复盘机制，确保发布可执行、可回滚、可追踪。

## 二、上线范围

阶段一上线范围仅包含：

1. 前端对话页面（Next.js）
2. 后端核心接口（FastAPI）
3. 搜索与LLM编排链路
4. 单一 Docker 配置部署（无 nginx）

## 三、上线前检查清单

### 1. 代码与配置

1. 接口文档与实现一致（见 [接口定义.md](/home/zhaoting/project/Agent/docs/阶段一MVP/接口定义.md)）。
2. Prompt版本已冻结并评审通过（见 [Prompt设计.md](/home/zhaoting/project/Agent/docs/阶段一MVP/Prompt设计.md)）。
3. `deploy/compose/docker-compose.yml` 与 `deploy/env/.env.example` 已更新。
4. 密钥未写入仓库，运行时通过环境注入。

### 2. 测试与质量

1. 功能测试通过（核心链路全部通过）。
2. 性能测试达标（首字 < 3s，完整 < 15s）。
3. 阻塞级缺陷（P0/P1）为 0。
4. 关键日志可追踪（requestId、错误码、时延）。

## 四、标准上线流程（SOP）

### 1. 部署命令

```bash
docker compose \
  -f deploy/compose/docker-compose.yml \
  --env-file deploy/env/.env.example \
  up -d --build
```

### 2. 发布步骤

1. 拉取目标版本代码。
2. 校验环境变量与密钥注入。
3. 执行容器构建与启动。
4. 执行健康检查（`/api/healthz`）。
5. 抽样验证核心接口：
   - `GET /api/suggestions`
   - `POST /api/chat`（SSE正常）
6. 观察关键指标 30 分钟，无异常后确认发布完成。

## 五、回滚方案

### 1. 触发条件

1. 连续出现高错误率（如 >5%）且持续 5 分钟以上。
2. 核心链路不可用（聊天接口不可用或SSE异常中断）。
3. 明显性能劣化（首字响应持续超阈值）。

### 2. 回滚动作

1. 切换到上一个稳定镜像/版本。
2. 重新执行 `docker compose up -d`。
3. 验证健康检查与核心链路恢复。
4. 冻结当前故障版本，进入缺陷排查流程。

## 六、上线后监控

### 1. 关键指标

1. 接口成功率
2. 首字响应时间（P50/P95/P99）
3. 完整响应时间
4. SSE中断率
5. 来源覆盖率
6. 上游错误率（Search/LLM）

### 2. 观察窗口

1. T+0 至 T+30 分钟：重点盯稳定性
2. T+30 分钟至 T+24 小时：重点盯时延与错误率
3. T+1 至 T+7 天：关注用户反馈与问题分布
