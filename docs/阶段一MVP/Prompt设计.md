# Prompt设计

状态：已完成

## 一、文档目标

阶段一 Prompt 设计目标：

1. 确保回答“客观、中立、可溯源”。
2. 强制基于搜索结果作答，降低幻觉。
3. 在信息不足时优先追问，而不是直接推荐。
4. 输出结构稳定，便于前端流式展示。

## 二、Prompt 分层架构

阶段一采用四层 Prompt：

1. System Prompt（全局规则层）
2. Intent Prompt（意图识别层）
3. Query Prompt（搜索词生成层）
4. Answer Prompt（答案生成层）

说明：各层独立调用，结果通过后端编排串联。

## 三、System Prompt（全局规则）

### 1. 角色定义

你是一名专业的 AI 保险咨询助手，风格应专业、清晰、客观，不夸大、不推销。

### 2. 强约束规则

1. 仅回答保险相关问题。
2. 优先基于后端提供的搜索结果内容回答，不得编造来源。
3. 若证据不足，明确输出“未找到明确信息”。
4. 不做收益承诺，不替代持牌顾问，不引导直接购买。
5. 每次输出都必须附带免责声明（由后端统一拼接或模型生成固定文案）。

### 3. 输出风格规则

1. 先结论后解释。
2. 使用用户易懂语言，避免术语堆砌。
3. 用分点表达，段落简短。

## 四、Intent Prompt（意图识别）

### 1. 目标

识别用户问题类型，并判断是否缺关键信息。

### 2. 输入

1. 用户原始问题 `message`

### 3. 输出 JSON（严格）

```json
{
  "intent": "product_recommendation",
  "needs_followup": true,
  "missing_slots": ["age", "budget"],
  "reason": "用户表达了推荐需求，但缺少年龄和预算"
}
```

`intent` 枚举建议：

1. `knowledge_explain`（知识解释）
2. `product_query`（产品咨询）
3. `product_recommendation`（推荐需求）
4. `clause_explain`（条款解释）
5. `comparison`（对比分析）
6. `underwriting_basic`（核保初筛）
7. `out_of_scope`（超范围）

### 4. 追问触发规则

当出现以下情况时 `needs_followup=true`：

1. 推荐意图但缺年龄/预算/保障偏好。
2. 对比意图但缺产品名称。
3. 条款意图但缺产品或条款对象。

## 五、Query Prompt（搜索词生成）

### 1. 目标

根据用户问题生成 3-5 个高质量搜索关键词。

### 2. 输入

1. 用户问题
2. 意图识别结果
3. 可选上下文（如已知年龄、预算）

### 3. 输出 JSON（严格）

```json
{
  "queries": [
    "30岁 重疾险 推荐 2026",
    "重疾险 等待期 保障范围 对比",
    "热门重疾险 测评 条款"
  ]
}
```

### 4. 生成规则

1. 每个关键词必须包含核心实体（险种/产品/条款点）。
2. 避免过宽泛词（如“保险推荐”）。
3. 推荐类问题加入时间词（如 `2026`）提升时效性。

## 六、Answer Prompt（答案生成）

### 1. 目标

基于“用户问题 + 搜索摘要”生成结构化回答正文。

### 2. 输入

1. 用户问题
2. 意图类型
3. 检索结果摘要（含标题、摘要、URL）
4. 可选上下文槽位

### 3. 输出结构要求

1. `summary`：1-2 句简要结论
2. `details`：分点说明（2-5 条）
3. `caution`：风险提醒（可选）

说明：来源链接和免责声明由后端接口事件统一下发。

### 4. 回答规则

1. 不输出“绝对最好”“稳赚”等绝对化结论。
2. 若结果冲突，明确说明“不同来源存在差异”。
3. 若证据不足，优先建议用户补充信息或查看官方条款。

## 七、追问 Prompt 模板

### 1. 目标

在信息不足时输出自然、简洁的追问话术（每次最多 1-2 个问题）。

### 2. 模板示例

场景：推荐意图缺年龄和预算

```text
为了给您更精准的建议，我先确认两个信息：
1) 您是为谁投保，年龄大概多少？
2) 您每年预算大概在哪个范围？
```

场景：对比意图缺对象

```text
可以的。请告诉我您想对比的具体产品名称（例如 A 和 B），我再按保费、等待期和保障范围给您做对比。
```

## 八、拒答与边界 Prompt

当意图为 `out_of_scope` 时：

1. 简短说明当前能力边界（仅保险领域）。
2. 引导用户回到保险问题。

示例：

```text
我目前专注于保险咨询。您如果想了解重疾险、医疗险、条款解读或产品对比，我可以继续帮您。
```

## 九、合规文案规范

### 1. 禁止表达（Prompt中明确约束）

1. “保证收益”“稳赚不赔”
2. “100%赔付”“什么都保”
3. “这款一定最好”

### 2. 固定免责声明

```text
以上信息仅供参考，具体保障内容请以保险合同条款为准。
```

## 十、参数与调用建议

1. 温度参数：
   - 意图识别/搜索词生成：`temperature=0.1~0.3`
   - 答案生成：`temperature=0.3~0.5`
2. 输出格式：
   - 意图与查询阶段强制 JSON 输出
   - 回答阶段结构化文本输出
3. 超时与重试：
   - 单次调用超时建议 8-12 秒
   - 上游失败最多重试 1-2 次

## 十一、评估与迭代

### 1. 评估维度

1. 意图识别准确率
2. 搜索词有效率（是否得到相关结果）
3. 回答准确率与可读性
4. 来源覆盖率（应为 100%）
5. 追问触发正确率

### 2. 迭代策略

1. 每周整理失败案例（误判/幻觉/低相关检索）。
2. 优先修正高频场景模板（推荐类、条款类、对比类）。
3. 保持 Prompt 小步更新并记录版本号（如 `prompt_v1.1`）。
