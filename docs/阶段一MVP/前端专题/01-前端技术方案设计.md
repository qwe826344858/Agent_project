# 前端技术方案设计（阶段一MVP）

状态：已完成

## 一、目标与范围

1. 支撑 MVP 问答核心链路：输入 -> 请求 -> 流式展示 -> 来源展示。
2. 提供稳定、简洁、可扩展的前端结构，便于后续阶段演进。
3. 范围仅包含：聊天页、推荐问题、SSE流式渲染、状态提示与错误提示。

## 二、技术选型

1. 框架：Next.js（App Router）
2. 语言：TypeScript
3. 样式：Tailwind CSS（或等效原子化样式方案）
4. 状态管理：React 内置状态 + 轻量 store（按需）
5. 网络通信：`fetch` + `ReadableStream`（SSE协议解析）

## 三、页面与模块设计

1. 页面：`/`（聊天主页面）
2. 核心模块：
   - `ChatInput`：输入与发送
   - `ChatMessageList`：消息渲染
   - `ThinkingStatus`：阶段状态（分析/搜索/整理）
   - `SuggestionList`：推荐问题
   - `ProductCardList`：产品推荐卡片（新增 — 双通道方案）
   - `SourceLinks`：来源列表

## 四、数据流设计

1. 用户提交问题后触发 `POST /api/chat`。
2. 前端持续读取 SSE 事件：
   - `status` 更新状态文案
   - `products` 渲染产品卡片（价格可能为 loading 态）
   - `delta` 追加回答文本
   - `products_update` 按 id 更新产品卡片价格
   - `sources` 渲染来源链接
   - `disclaimer` 渲染免责声明
   - `done` 结束当前请求
3. 异常事件 `error` 触发错误提示与重试入口。
4. 产品卡片渲染策略：
   - 收到 `products` 时立即渲染骨架（名称/平台/标签可见，价格显示 loading 动画）
   - 收到 `products_update` 时按 id 匹配更新价格，loading 动画替换为真实价格
   - 点击卡片跳转到保险平台商品详情页（新窗口打开）

## 五、关键交互与约束

1. 发送后禁止重复点击，防止并发请求污染上下文。
2. 流式输出期间允许“停止生成”（可选）。
3. 所有回答必须显示来源区块与免责声明区块。
4. 保持移动端可用（输入区固定、消息区可滚动）。

## 六、可扩展性设计

1. 事件协议与渲染层解耦，便于后续新增事件类型。
2. 消息结构统一建模，后续可扩展卡片消息。
3. 组件分层清晰，阶段二新增能力不破坏阶段一主链路。
