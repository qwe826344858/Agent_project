状态：待评审
关联文档：

- LLM部分：`LLM专题/05-产品推荐双通道方案-LLM.md`

## 一、问题背景

当前产品推荐链路中，保险商品的名称、价格、投保链接全部由 LLM 从搜索结果摘要中生成。存在以下问题：

1. LLM 输出的"投保链接"实际是文章/测评页面，不是真实的商品投保页面。
2. LLM 可能编造或混淆价格信息。
3. 用户无法直接从回答中跳转到保险平台完成投保。

## 二、设计目标

1. 产品卡片（名称、价格、投保链接）由**代码逻辑**精确控制，不经过 LLM。
2. LLM 只负责生成文字建议（选购分析、对比、风险提示）。
3. 采用渐进式加载：先展示卡片骨架 → 异步补充价格。

## 三、双通道架构

> **架构变更（2026-03-25）**：通道A 从「搜索引擎 site: 限定搜索」改为「平台直连 API」，直接调用各保险平台的搜索 API 获取结构化产品数据，不再需要白名单 URL 过滤、HEAD 校验、搜索引擎 site: 限定。

```
用户提问
    │
    ▼
意图识别（LLM）+ 预算提取
    │
    ├────────────────────────────────────┐
    ▼                                    ▼
【通道A：产品卡片】                【通道B：文字建议】
平台直连 API，不经过 LLM            LLM 流式生成
    │                                    │
    ▼                                    ▼
1. 调用各平台搜索 API              1. fallback 静态知识库
   (小雨伞/平安/慧择)                 (通用保险知识)
    │                                    │
    ▼                                    ▼
2. 获取结构化产品数据               2. LLM 生成选购建议
   (名称/价格/平台/链接)              (对比分析/风险提示)
    │                                    │
    ▼                                    ▼
3. 预算筛选与排序                   3. SSE: delta 事件
   (预算内优先，容差50%)               (流式文本)
    │                                    │
    ▼                                    ▼
4. SSE: products 事件               前端渲染文字区域
   (含价格的结构化 JSON)
```

> **注意**：由于平台直连 API 直接返回结构化数据（含价格），`products` 事件已包含价格信息，`products_update` 事件变为可选（仅在需要补充额外详情时使用）。

## 四、SSE 事件协议变更

新增 `products` 事件，`products_update` 变为可选。

### 4.1 `products`

平台直连 API 返回后立即推送，已包含价格信息（由平台 API 直接返回结构化数据）。

```text
event: products
data: {
  "items": [
    {
      "id": "prod_001",
      "name": "众安尊享e生·百万医疗保险2026版",
      "company": "众安保险",
      "price": "258元/年起",
      "price_label": "258元/年起",
      "tags": ["百万医疗", "保证续保"],
      "url": "https://www.xiaoyusan.com/insurance/detail?id=178938",
      "platform": "小雨伞",
      "brief": "最高600万保额，不限社保"
    }
  ]
}
```

### 4.2 `products_update`（可选）

仅在需要补充额外详情（如保障摘要更新）时推送，按 `id` 更新对应卡片。平台直连 API 已返回价格，通常无需此事件。

```text
event: products_update
data: {
  "items": [
    {
      "id": "prod_001",
      "brief": "一般医疗200万+重疾医疗400万，含质子重离子"
    }
  ]
}
```

### 4.3 完整 SSE 事件时序

```
status(analyzing) → status(searching) → products(含价格的完整卡片)
→ status(answering) → delta*(文字流式)
→ sources → disclaimer → done
```

## 五、新增模块：平台直连 API（PlatformAPI）

目录：`app/services/platform_apis/`

> **方案变更（2026-03-25）**：原 `ProductSearchService` 通过搜索引擎 `site:` 限定搜索的方案已废弃，改为直接调用各保险平台的搜索 API 获取结构化产品数据。

### 5.1 职责

1. 直接调用各保险平台的搜索 API，获取结构化产品数据（名称、价格、链接、标签等）。
2. 统一抽象接口，新增平台只需继承 `PlatformAPI` 基类并实现 `search()` 方法。
3. 不再需要白名单 URL 过滤、HEAD 校验、搜索引擎 `site:` 限定、HTML 解析。

### 5.2 目录结构

```
app/services/platform_apis/
├── __init__.py      # 平台注册表，统一导出
├── base.py          # PlatformAPI 抽象基类
├── xiaoyusan.py     # 小雨伞平台 API
├── pingan.py        # 平安平台 API
└── huize.py         # 慧择平台 API
```

### 5.3 核心接口

```python
# base.py — 抽象基类
class PlatformAPI(ABC):
    """保险平台搜索 API 抽象基类"""

    @abstractmethod
    async def search(self, keyword: str, **kwargs) -> list[ProductCard]:
        """调用平台搜索 API，返回结构化产品列表"""
        ...
```

```python
# __init__.py — 平台注册
from .xiaoyusan import XiaoYuSanAPI
from .pingan import PingAnAPI
from .huize import HuiZeAPI

PLATFORM_REGISTRY: list[PlatformAPI] = [
    XiaoYuSanAPI(),
    PingAnAPI(),
    HuiZeAPI(),
]
```

### 5.4 搜索策略

1. 从用户问题中提取险种关键词（医疗险/重疾险/意外险等）。
2. 并行调用所有已注册平台的 `search()` 方法。
3. 平台 API 直接返回结构化数据（含价格），无需二次抓取 HTML。
4. 合并各平台结果，去重后返回。

### 5.5 预算筛选

1. 从用户输入中提取年预算（如"预算1000元"）。
2. 产品价格统一估算为年缴（月缴 x 12）。
3. 按与预算的匹配度排序，预算内产品优先展示。
4. 容差 50%（如预算 1000 元 → 上限 1500 元）。

### 5.6 扩展新平台

新增平台只需：
1. 在 `platform_apis/` 下新建文件，继承 `PlatformAPI` 并实现 `search()` 方法。
2. 在 `__init__.py` 中注册到 `PLATFORM_REGISTRY`。

注意事项：
- 各平台 API 调用设置超时时间（5 秒）与重试策略（指数退避，最多 1 次）。
- 结果可缓存（Redis，TTL 30 分钟）。
- 价格获取失败时显示"查看详情"而非空白。

## 六、数据模型变更

`app/schemas/chat.py` 新增：

```python
class ProductCard(BaseModel):
    id: str
    name: str
    company: str = ""
    price: str | None = None
    price_label: str = "加载中"
    tags: list[str] = []
    url: str
    platform: str
    brief: str = ""

class SSEProductsPayload(BaseModel):
    items: list[ProductCard]

class SSEProductsUpdatePayload(BaseModel):
    items: list[ProductCard]
```

## 七、编排器变更

`ChatOrchestrator.run_stream()` 流程变更为：

```
1. 意图识别（LLM）+ 预算提取
2. 判断追问/超范围
3. 并行执行：
   a. 通道A：调用平台直连 API 搜索产品 → 预算筛选排序 → 推送 products 事件（含价格）
   b. 通道B：fallback 静态知识库 + LLM 回答 → 推送 delta 事件
4. 推送 sources / disclaimer / done
```

> **变更说明**：通道A 改为平台直连 API，产品数据已含价格，无需异步抓取详情页，`products_update` 步骤已移除。通道B 的通用搜索改为 fallback 静态知识库（不再依赖 MiniMax Search API / Open-WebSearch MCP）。

## 八、不触发产品推荐的场景

仅以下意图触发产品搜索（推送 `products` 事件）：
- `product_recommendation`（推荐需求）
- `product_query`（产品咨询）
- `comparison`（对比分析）

以下意图不触发，仅走文字回答：
- `knowledge_explain`、`clause_explain`、`underwriting_basic`、`out_of_scope`、追问
