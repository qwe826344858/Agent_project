# 阶段一（MVP）需求梳理与阶段拆解

## 一、需求梳理

### 1. 阶段目标

1. 验证 Search-First（搜索优先）在保险咨询场景的可行性。
2. 跑通最小闭环：提问 -> 搜索 -> 汇总 -> 溯源 -> 流式展示。
3. 在 1 至 2 周内完成可上线的最小可行版本。

### 2. 用户与核心场景

1. 目标用户：
   - 保险新手
   - 主动了解者
   - 潜在购买者
2. 核心场景：
   - 保险知识查询
   - 产品信息咨询
   - 基础方案推荐咨询
   - 条款术语解读

### 3. MVP功能范围

1. `F1.1` 自然语言问答  
   支持保险基础概念、产品咨询、条款解读、险种对比等问题。
2. `F1.2` 联网搜索能力  
   自动拆解问题并生成搜索词，调用搜索服务，提取有效信息。
3. `F1.3` 来源溯源  
   所有回答必须带来源链接，支持用户核查。
4. `F1.4` 基础流式输出  
   使用 SSE 返回内容，前端逐步渲染，减少等待焦虑。
5. 智能追问机制  
   用户信息不足时主动追问关键槽位（年龄、预算、需求方向）。

### 4. 非功能需求

1. 首字响应时间小于 3 秒。
2. 完整响应时间小于 15 秒。
3. 来源覆盖率 100%。
4. 常见问题回答准确率大于 80%（MVP验收口径）。
5. 基础并发能力达到 50 QPS。

### 5. 合规与边界

1. 输出信息保持客观、中立，不诱导购买。
2. 每次回答附加免责声明。
3. 不做收益承诺，不替代持牌顾问，不提供非保险领域建议。

### 6. 技术实现最小集

1. 前端：
   - 首页推荐问题
   - 对话输入与消息渲染
   - 流式输出展示
   - 思考状态文案
2. 后端：
   - `POST /api/chat`
   - `GET /api/suggestions`
   - 搜索与LLM编排逻辑
3. Prompt：
   - 角色设定
   - 回答风格
   - 来源标注规范
   - 免责声明模板

## 二、阶段拆解（1-2周）

### 1. D1-D2：需求冻结与方案设计

1. 完成需求评审与范围冻结（明确做与不做）。
2. 确认接口草案、数据流与错误处理策略。
3. 确认提示词框架、搜索策略与来源展示规范。
4. 准备测试问题集（不少于 50 条）。

交付物：

1. 技术方案文档（架构、接口、数据流）。
2. 页面原型/交互草图。
3. 测试用例清单（功能 + 性能）。

### 2. D3-D5：核心功能开发

1. 开发对话主链路：消息接收、意图分析、搜索编排、答案生成。
2. 打通 SSE 流式输出链路。
3. 实现来源链接拼装与统一输出格式。
4. 完成首页推荐问题接口与前端展示。

交付物：

1. MVP可运行版本（前后端联调可用）。
2. 基础日志与错误码定义。

### 3. D6-D7：Prompt与搜索效果优化

1. 优化搜索词生成，降低无关结果占比。
2. 优化回答结构，提升可读性与稳定性。
3. 落地智能追问策略（缺信息时不盲答）。
4. 加强广告/软文识别与低质量来源过滤。

交付物：

1. Prompt v2版本。
2. 搜索策略优化报告（示例问题前后对比）。

### 4. D8-D10：测试与修复

1. 功能测试：问答、搜索、溯源、流式、追问。
2. 性能测试：首字时延、全链路时延、并发压测。
3. 回归测试并修复阻塞上线的问题。

交付物：

1. 测试报告（功能/性能/缺陷清单）。
2. 修复后的候选发布版本（Release Candidate）。

### 5. D11-D14：上线与观察优化

1. 完成基于单一 `docker-compose.yml` 的标准发布流程。
2. 跟踪核心指标：时延、准确率、来源覆盖率、满意度。
3. 收集真实用户问题，为阶段二形成需求输入。

交付物：

1. 上线记录与监控面板。
2. 阶段复盘报告。
3. 阶段二需求输入清单。

## 三、阶段一验收清单

1. 端到端流程可用（提问到回答完整闭环）。
2. 100%回答包含至少一个来源链接。
3. 首字响应时间小于 3 秒。
4. 常见问题回答准确率达到目标。
5. 流式输出稳定，无明显卡顿或中断异常。
