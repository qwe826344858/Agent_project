# 接口定义（未完成）

状态：未完成（已完成第一版初稿）

## 一、文档范围

本文档仅覆盖阶段一（MVP）接口，不包含阶段二及以上能力（用户体系、历史会话管理、文件上传、知识库检索等）。

后端主框架：FastAPI  
通信方式：HTTP + SSE

## 二、通用约定

### 1. 基础信息

1. Base URL：`/api`
2. Content-Type：`application/json`（SSE除外）
3. 编码：UTF-8
4. 时间字段：ISO 8601（如 `2026-03-17T15:00:00+08:00`）

### 2. 鉴权与限流（阶段一）

1. 阶段一默认无登录鉴权。
2. 预留网关级限流能力（如按 IP 限制）。

### 3. 通用错误响应（非SSE）

```json
{
  "error": {
    "code": "INVALID_ARGUMENT",
    "message": "message 不能为空",
    "requestId": "req_01J..."
  }
}
```

## 三、接口清单

1. `POST /api/chat`：对话主接口（SSE流式）。
2. `GET /api/suggestions`：首页推荐问题。
3. `GET /api/healthz`：健康检查。

## 四、POST /api/chat（SSE）

### 1. 接口说明

用于处理用户问题并流式返回回答内容、来源信息和状态事件。

### 2. 请求参数

```json
{
  "message": "30岁买什么重疾险比较好？",
  "sessionId": "sess_abc123",
  "requestId": "req_abc123"
}
```

字段说明：

1. `message`：`string`，必填，用户问题。
2. `sessionId`：`string`，可选，会话标识（MVP可由前端生成并复用）。
3. `requestId`：`string`，可选，链路追踪标识；未传则后端生成。

### 3. 响应头

1. `Content-Type: text/event-stream`
2. `Cache-Control: no-cache`
3. `Connection: keep-alive`

### 4. SSE事件定义

#### 4.1 `status`

用于告知当前处理阶段。

```text
event: status
data: {"stage":"analyzing","message":"正在分析需求"}
```

`stage` 枚举：

1. `analyzing`
2. `searching`
3. `reading`
4. `answering`

#### 4.2 `delta`

用于增量输出回答正文。

```text
event: delta
data: {"text":"建议优先关注保障范围与等待期。"}
```

#### 4.3 `sources`

用于返回来源列表（通常在正文结束后一次性发送）。

```text
event: sources
data: {
  "items":[
    {"title":"某产品测评","url":"https://example.com/a","site":"example.com"},
    {"title":"保险公司官网条款","url":"https://example.com/b","site":"example.com"}
  ]
}
```

#### 4.4 `disclaimer`

固定风险提示文案。

```text
event: disclaimer
data: {"text":"以上信息仅供参考，具体保障内容请以保险合同条款为准。"}
```

#### 4.5 `done`

表示流式输出完成。

```text
event: done
data: {"requestId":"req_abc123"}
```

#### 4.6 `error`

表示本次请求失败并终止流。

```text
event: error
data: {"code":"UPSTREAM_TIMEOUT","message":"上游服务超时","requestId":"req_abc123"}
```

#### 4.7 `products`（双通道产品推荐 — 平台直连 API）

平台直连 API 返回后立即推送保险商品卡片，已包含价格信息（由平台 API 直接返回结构化数据）。
仅在推荐类/产品查询类/对比类意图时推送。产品按预算匹配度排序（预算内优先，容差 50%）。

```text
event: products
data: {
  “items”: [
    {
      “id”: “prod_001”,
      “name”: “众安尊享e生·百万医疗保险2026版”,
      “company”: “众安保险”,
      “price”: “258元/年起”,
      “price_label”: “258元/年起”,
      “tags”: [“百万医疗”, “保证续保”],
      “url”: “https://www.xiaoyusan.com/insurance/detail?id=178938”,
      “platform”: “小雨伞”,
      “brief”: “最高600万保额，不限社保”
    }
  ]
}
```

#### 4.8 `products_update`（可选 — 补充信息更新）

> **变更说明（2026-03-25）**：由于改为平台直连 API，`products` 事件已包含价格，`products_update` 变为可选事件。仅在需要补充额外详情（如保障摘要更新）时推送。前端应保留处理逻辑以兼容后续扩展。

```text
event: products_update
data: {
  “items”: [
    {
      “id”: “prod_001”,
      “brief”: “一般医疗200万+重疾医疗400万，含质子重离子”
    }
  ]
}
```

#### 事件时序（产品推荐场景）

```
status(analyzing) → status(searching) → products(含价格的完整卡片) → status(answering)
→ delta*(文字流式) → sources → disclaimer → done
```

### 5. 业务规则

1. 当用户问题信息不足时，返回追问内容，不执行搜索。
2. 回答末尾必须包含来源事件与免责声明事件。
3. 当无法确认信息时，正文需明确”未找到明确信息”。
4. **产品推荐场景**：`products` 事件中的产品数据（含价格、投保链接）来自保险平台直连 API 的结构化返回，不得由 LLM 生成。
5. **产品卡片与文字回答独立**：产品卡片由平台直连 API 提供（通道A），文字建议由 LLM 基于静态知识库生成（通道B），两者并行不阻塞。
6. **预算筛选**：若用户提供预算信息，产品按与预算的匹配度排序，预算内优先展示，容差 50%。

### 6. 典型错误码

1. `INVALID_ARGUMENT`：请求参数非法。
2. `RATE_LIMITED`：触发限流。
3. `UPSTREAM_TIMEOUT`：搜索或模型调用超时。
4. `UPSTREAM_ERROR`：上游服务异常。
5. `INTERNAL_ERROR`：系统内部错误。

## 五、GET /api/suggestions

### 1. 接口说明

返回首页推荐问题列表。

### 2. 请求参数

无

### 3. 成功响应

```json
{
  "suggestions": [
    "重疾险和医疗险有什么区别？",
    "百万医疗险怎么选？",
    "什么是免赔额？",
    "意外险通常保哪些场景？",
    "等待期是什么意思？"
  ]
}
```

### 4. 失败响应

按通用错误结构返回。

## 七、前后端联调约定

1. 前端建立 `EventSource`（或 fetch + stream）后，按事件类型更新 UI。
2. `status` 事件用于思考状态条；`delta` 事件用于正文流式拼接。
3. 收到 `done` 后结束本轮；收到 `error` 后展示错误并允许重试。

## 八、版本与兼容策略

1. 当前版本：`v1`（阶段一MVP）。
2. 新增字段遵循向后兼容，不删除既有字段。
3. 重大变更通过 `/api/v2/...` 新路径引入。
