## 二、测试目标

1. 验证阶段一核心闭环：提问 -> 搜索 -> 汇总 -> 溯源 -> 流式输出。
2. 验证接口与事件协议符合 [接口定义.md](/home/zhaoting/project/Agent/docs/阶段一MVP/接口定义.md)。
3. 验证关键指标达标：
   - 首字响应 < 3 秒
   - 完整响应 < 15 秒
   - 来源覆盖率 = 100%

## 三、测试环境

1. 部署方式：`docker-compose` 单配置
2. 运行命令：
   - `docker compose -f deploy/compose/docker-compose.yml --env-file deploy/env/.env.example up -d --build`
3. 环境要求：
   - 后端 FastAPI
   - 前端 Next.js
   - Redis / Postgres（按需启用）

## 五、测试用例（样例）

### 1. 功能用例

1. 用例 `FUNC-001`：保险概念解释  
输入：“什么是免赔额？”  
期望：回答准确、语言通俗、含来源和免责声明。

2. 用例 `FUNC-002`：产品推荐追问  
输入：“推荐个保险”  
期望：触发追问（年龄、预算等），不直接给结论。

3. 用例 `FUNC-003`：产品对比  
输入：“A和B哪个好？”  
期望：若对象不明确先追问；明确后给出结构化比较。

### 2. 接口用例

1. 用例 `API-001`：`/api/chat` 正常流  
期望事件顺序：`status* -> delta* -> sources -> disclaimer -> done`

2. 用例 `API-002`：`/api/suggestions`  
期望：返回 3-5 条推荐问题，数组非空。

3. 用例 `API-003`：`/api/healthz`  
期望：返回 `status=ok`。

### 3. 性能用例

1. 用例 `PERF-001`：单请求时延  
期望：首字 < 3s，完整 < 15s。

2. 用例 `PERF-002`：并发压测  
期望：50 QPS 下错误率在可接受范围（目标 < 1%）。
