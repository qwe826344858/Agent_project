# 产品详情查询功能方案

状态：待评审
优先级：阶段二 — 核心新功能

---

## 一、功能概述

用户在产品卡片中点击"查看保障详情"按钮后，前端携带 `action: "product_detail"` 和 `product_url` 直接请求后端。编排器识别到 action 后**跳过意图识别**，直接调用 `ProductDetailSkill`，由 Skill 完成"抓取→清洗→LLM提取→校验→LLM翻译"完整链路。已提取的数据以全局 URL 级缓存存储（TTL 1 天），后续追问不重复抓取。

### 1.1 关键设计决策

| 决策 | 方案 | 原因 |
|---|---|---|
| 触发方式 | 前端按钮传 `action` + `product_url` | 跳过意图识别省 3-5s，且前端已持有产品信息 |
| 自然语言触发 | 阶段二暂不支持"详细说说第2款" | 需要会话上下文记忆产品列表，复杂度高，后续迭代 |
| 会话状态 | 无状态，产品信息由前端传入 | 避免引入会话存储层，保持架构简单 |

## 二、整体链路

```
用户点击产品卡片上的"查看保障详情"按钮
    ↓
前端构造请求：
  POST /api/chat
  { message: "", action: "product_detail", productUrl: "...", productName: "..." }
    ↓
chat.py（API 入口）→ orchestrator_adapter → chat_orchestrator
    ↓
编排器入口判断 action
    ├── action == "product_detail" → 跳过意图识别，直接调用 Skill
    └── 其他 → 原有流程不变
    ↓
ProductDetailSkill.run(product_url, product_name, user_question)
    ↓
① 查全局缓存（key=URL，TTL=1天）
    ├── 命中 → 直接跳到 ⑥
    └── 未命中 → 继续
    ↓
② HTTP 抓取网页 HTML
    ↓
③ BeautifulSoup 通用清洗
    - 删除 <script>、<style>、<nav>、<footer>、<header>、<iframe>
    - 删除所有 HTML 属性
    - 只保留正文纯文本
    - 统计中文字符数（校验基线）
    ↓
④ LLM 第 1 轮：结构化提取
    输入：清洗后的纯文本
    输出：JSON 格式的保障项列表
    ↓
⑤ 代码校验（字符回查匹配）
    ├── 匹配率 ≥ 70% → 通过，写入全局缓存
    └── 匹配率 < 70% → 重试（调整 Prompt），最多 3 次
         └── 仍失败 → 降级提示用户
    ↓
⑥ LLM 第 2 轮：基于缓存的结构化数据 + 用户问题 → 通俗话术
    ↓
⑦ SSE 流式输出（detail_items + delta）
```

## 三、Agent-Skill 编排架构

### 3.1 设计思路

编排器（Agent）不直接处理网页抓取和 LLM 多轮调用的细节，而是通过调用 **ProductDetailSkill** 完成整个"抓取 → 提取 → 校验 → 翻译"链路。Skill 内部封装了两轮 LLM、校验重试、缓存读写等逻辑，对编排器而言是一个黑盒。

**关键**：前端按钮点击通过 `action` 字段直达 Skill，**跳过 LLM 意图识别**，节省 3-5s。

```
前端点击"查看保障详情"
    ↓
POST /api/chat { action: "product_detail", productUrl, productName }
    ↓
chat.py → 传递 action/productUrl/productName 给编排器
    ↓
ChatOrchestrator（Agent 编排层）
    │
    ├── action == "product_detail" ? → 跳过意图识别
    │
    └── 直接调用 ProductDetailSkill.run(url, name, question)
            │
            ├── Step 1: 查缓存
            │     ├── 命中 → 跳到 Step 4
            │     └── 未命中 → 继续
            │
            ├── Step 2: 抓取 + 清洗
            │     HTTP GET → BeautifulSoup 清洗 → 纯文本 + 中文字符数
            │
            ├── Step 3: LLM 第 1 轮 — 结构化提取（带校验重试）
            │     ┌─────────────────────────────┐
            │     │  提取 → 校验(字符回查)       │
            │     │    ├── 通过 → 写缓存         │
            │     │    └── 不通过 → 调整重试      │
            │     │         （最多 3 次）         │
            │     └─────────────────────────────┘
            │     这是链路中唯一的"有限循环"环节
            │
            ├── Step 4: LLM 第 2 轮 — 通俗化输出
            │     输入：结构化数据 + 用户问题
            │     输出：流式 delta 文字
            │
            └── 返回给编排器 → SSE 推送给前端
```

### 3.7 Skill 内部流程实现

```python
class ProductDetailSkill:

    async def run(self, product_url, product_name="", user_question=""):
        # ---- Step 1: 查缓存 ----
        cached = product_detail_cache.get(product_url)
        if cached:
            logger.info("缓存命中: %s", product_url)
            # 追问场景：直接用缓存数据 + 用户问题生成回答
            async for chunk in self._generate_answer(cached, user_question):
                yield {"event": "delta", "data": {"text": chunk}}
            return

        # ---- Step 2: 抓取 + 清洗 ----
        yield {"event": "status", "data": {"stage": "reading", "message": "正在读取产品页面..."}}

        raw_html = await self._fetch_page(product_url)
        if not raw_html:
            yield {"event": "delta", "data": {"text": f"暂时无法访问该产品页面，建议直接查看：{product_url}"}}
            return

        cleaned_text, cn_count = clean_html(raw_html)
        logger.info("网页清洗完成: %d 中文字符", cn_count)

        if cn_count < 50:
            yield {"event": "delta", "data": {"text": f"该页面内容较少，无法提取保障详情，建议直接查看：{product_url}"}}
            return

        # ---- Step 3: LLM 第 1 轮 — 结构化提取（带校验重试） ----
        yield {"event": "status", "data": {"stage": "analyzing", "message": "正在分析保障项目..."}}

        detail = await self._extract_with_retry(
            cleaned_text=cleaned_text,
            cn_count=cn_count,
            product_url=product_url,
            product_name=product_name,
            max_retries=3,
        )

        if not detail:
            yield {"event": "delta", "data": {"text": f"暂时无法自动解析此产品的保障详情，建议直接查看：{product_url}"}}
            return

        # 推送结构化数据
        yield {"event": "detail_items", "data": detail.model_dump()}

        # 写入全局缓存
        product_detail_cache.set(product_url, detail)

        # ---- Step 4: LLM 第 2 轮 — 通俗化输出 ----
        yield {"event": "status", "data": {"stage": "answering", "message": "正在生成通俗解读..."}}

        async for chunk in self._generate_answer(detail, user_question):
            yield {"event": "delta", "data": {"text": chunk}}

    async def _extract_with_retry(self, cleaned_text, cn_count, product_url, product_name, max_retries=3):
        """带校验重试的结构化提取"""
        for attempt in range(1, max_retries + 1):
            # 第 3 次尝试时缩短输入文本
            input_text = cleaned_text[:3000] if attempt == 3 else cleaned_text

            # LLM 提取
            raw_json = await llm_client.call_text(
                system_prompt=DETAIL_EXTRACT_SYSTEM_PROMPT,
                user_prompt=DETAIL_EXTRACT_PROMPT.format(cleaned_text=input_text),
            )
            duties = self._parse_duties_json(raw_json)

            if not duties:
                logger.warning("第 %d 次提取: JSON 解析失败", attempt)
                continue

            # 字符回查校验
            passed, match_rate, reason = validate_extraction(duties, cleaned_text, cn_count)
            logger.info("第 %d 次提取: %s (匹配率 %.0f%%)", attempt, reason, match_rate * 100)

            if passed:
                return ProductDetail(
                    product_name=product_name or duties[0].name if duties else "",
                    product_url=product_url,
                    duties=duties,
                    cn_char_count=cn_count,
                    match_rate=match_rate,
                )

        logger.warning("3 次提取均未通过校验: %s", product_url)
        return None

    async def _generate_answer(self, detail, user_question):
        """LLM 第 2 轮：基于结构化数据生成通俗回答"""
        duties_text = "\n".join(
            f"- {d.name}（{d.coverage}）{'【可选】' if d.is_optional else ''}: {d.description}"
            for d in detail.duties
        )
        if user_question:
            # 追问场景
            prompt = DETAIL_FOLLOWUP_PROMPT.format(
                product_name=detail.product_name,
                duties_formatted=duties_text,
                user_question=user_question,
            )
        else:
            # 首次查询
            prompt = DETAIL_EXPLAIN_PROMPT.format(
                product_name=detail.product_name,
                duties_formatted=duties_text,
            )
        async for chunk in llm_client.call_text_stream(
            system_prompt=DETAIL_EXPLAIN_SYSTEM_PROMPT,
            user_prompt=prompt,
        ):
            yield chunk
```

### 3.8 各层职责边界

| 层级 | 职责 | 不负责 |
|---|---|---|
| **ChatOrchestrator（Agent）** | 意图路由、提取产品 URL、透传 SSE 事件 | 不关心抓取/提取/校验细节 |
| **ProductDetailSkill** | 编排完整链路：缓存→抓取→清洗→提取→校验→翻译 | 不关心前端展示和意图识别 |
| **clean_html()** | HTML → 纯文本 + 字符统计 | 不关心文本含义 |
| **LLM 第 1 轮** | 纯文本 → 结构化 JSON | 不做通俗翻译 |
| **validate_extraction()** | 校验 JSON 是否有据可查 | 不修正结果 |
| **LLM 第 2 轮** | 结构化数据 → 通俗话术 | 不做提取 |
| **ProductDetailCache** | URL → ProductDetail 的存取 | 不关心数据怎么来的 |

### 3.9 Skill 可复用性

`ProductDetailSkill` 封装为独立类，未来可被以下场景复用：

| 场景 | 调用方式 |
|---|---|
| 用户点击"查看保障详情"按钮 | 编排器 → `skill.run(url)` |
| 用户自然语言"详细说说第2款" | 编排器匹配序号 → `skill.run(url)` |
| 用户追问"免赔额怎么算" | 编排器 → `skill.run(url, question=...)` → 缓存命中，1 轮 LLM |
| 批量预热缓存（后台任务） | 直接调用 `skill.run(url)` 预提取 |

## 四、通用网页清洗

### 4.1 工具选择

使用 `BeautifulSoup`（Python 标准 HTML 解析库），不依赖任何外部服务。

### 4.2 清洗规则

```python
from bs4 import BeautifulSoup
import re

# 需要删除的标签（不保留内容）
REMOVE_TAGS = {"script", "style", "nav", "footer", "header", "iframe", "noscript", "svg", "img"}

# 需要保留的正文标签
KEEP_TAGS = {"p", "div", "span", "li", "td", "th", "h1", "h2", "h3", "h4", "h5", "h6", "a", "strong", "em", "b"}

def clean_html(raw_html: str) -> tuple[str, int]:
    """通用 HTML 清洗，返回 (纯文本, 中文字符数)"""
    soup = BeautifulSoup(raw_html, "html.parser")

    # 删除噪音标签
    for tag in soup.find_all(REMOVE_TAGS):
        tag.decompose()

    # 提取纯文本
    text = soup.get_text(separator="\n", strip=True)

    # 合并连续空行
    text = re.sub(r'\n{3,}', '\n\n', text)

    # 统计中文字符数
    cn_count = len(re.findall(r'[\u4e00-\u9fff]', text))

    return text, cn_count
```

### 4.3 文本截断策略

| 中文字符数 | 处理 |
|---|---|
| ≤ 5000 字 | 全文送入 LLM |
| 5000-10000 字 | 截取前 5000 字（保险产品保障信息通常在页面上半部分） |
| > 10000 字 | 截取前 5000 字 + 末尾 1000 字（兜住增值服务等尾部内容） |

## 六、校验机制：字符回查匹配

### 6.1 核心逻辑

LLM 提取的每项保障名称，回到原始清洗文本中搜索，能找到的算"有据可查"，找不到的算"疑似幻觉"。

```python
def validate_extraction(
    duties: list[DutyItem],
    cleaned_text: str,
    cn_char_count: int,
) -> tuple[bool, float, str]:
    """校验 LLM 提取结果的准确性

    Returns:
        (是否通过, 匹配率, 原因描述)
    """
    if not duties:
        return False, 0.0, "未提取到任何保障项"

    # 逐项回查：保障名称的核心词是否在原文中出现
    matched = 0
    for duty in duties:
        # 提取名称中的核心关键词（去掉"保险金""医疗""费用"等通用词）
        core = re.sub(r'(保险金|医疗|费用|责任|保障)', '', duty.name)
        # 至少保留 2 个中文字符作为匹配依据
        core_chars = re.findall(r'[\u4e00-\u9fff]{2,}', core)

        if not core_chars:
            # 名称全是通用词，用完整名称匹配
            if duty.name in cleaned_text:
                matched += 1
        elif any(c in cleaned_text for c in core_chars):
            matched += 1

    match_rate = matched / len(duties) if duties else 0
    reason = f"匹配 {matched}/{len(duties)} 项 ({match_rate:.0%})"

    # 匹配率 ≥ 70% 视为通过
    passed = match_rate >= 0.7
    return passed, match_rate, reason
```

### 6.2 失败处理

```
第 1 次提取 → 校验
    ├── 通过 → 存缓存
    └── 不通过 → 调整 Prompt 重试（增加提示："请仅提取页面中明确出现的保障项"）
         → 第 2 次提取 → 校验
              ├── 通过 → 存缓存
              └── 不通过 → 第 3 次（最后一次）：缩短输入文本，只取前 3000 字
                   → 校验
                        ├── 通过 → 存缓存
                        └── 不通过 → 降级提示用户
```

**降级文案**：
```
暂时无法自动解析此产品的保障详情，建议您直接访问产品页面查看：{url}
```

## 七、全局缓存设计

### 7.1 缓存结构

```python
from dataclasses import dataclass, field
from datetime import datetime, timedelta
import threading

@dataclass
class CacheEntry:
    detail: ProductDetail        # 结构化保障数据
    created_at: datetime         # 创建时间
    ttl: timedelta = field(default_factory=lambda: timedelta(days=1))

    @property
    def is_expired(self) -> bool:
        return datetime.now() - self.created_at > self.ttl

class ProductDetailCache:
    """全局 URL 级缓存，TTL 1 天"""

    def __init__(self):
        self._store: dict[str, CacheEntry] = {}
        self._lock = threading.Lock()

    def get(self, url: str) -> ProductDetail | None:
        with self._lock:
            entry = self._store.get(url)
            if entry and not entry.is_expired:
                return entry.detail
            if entry and entry.is_expired:
                del self._store[url]
            return None

    def set(self, url: str, detail: ProductDetail):
        with self._lock:
            self._store[url] = CacheEntry(
                detail=detail,
                created_at=datetime.now(),
            )

    def clear_expired(self):
        """清理过期缓存（可定时调用）"""
        with self._lock:
            expired = [k for k, v in self._store.items() if v.is_expired]
            for k in expired:
                del self._store[k]

# 全局单例
product_detail_cache = ProductDetailCache()
```

## 十三、验收标准

| 项目 | 标准 |
|---|---|
| 网页清洗 | 任意保险产品页面，清洗后纯文本不含 HTML 标签/JS/CSS |
| 结构化提取 | 提取保障项 ≥ 3 项，每项含 name + coverage |
| 字符回查 | 匹配率 ≥ 70% 视为通过 |
| 幻觉控制 | LLM 输出的保障项名称可在原文中找到 |
| 重试机制 | 首次不通过时自动重试，最多 3 次 |
| 降级处理 | 3 次均失败时，输出友好提示 + 产品链接 |
| 缓存命中 | 同 URL 第二次查询不重新抓取 |
| 追问响应 | 缓存命中时只需 1 轮 LLM，耗时 3-5s |
| 通俗话术 | 每项保障用大白话说清楚，300-500 字 |
| 前端展示 | 结构化卡片 + 流式文字双重展示 |
