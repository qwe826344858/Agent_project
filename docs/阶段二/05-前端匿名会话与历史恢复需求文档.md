# 前端匿名会话与历史恢复需求文档

状态：方案设计中
适用范围：前端聊天页面、会话初始化、聊天记录恢复、匿名用户本地标识

## 一、背景

当前聊天页面主要依赖前端内存状态维护消息列表。用户刷新页面、关闭页面后再次进入时，页面无法稳定恢复上一次聊天内容；后端也无法可靠识别本次请求属于哪个历史会话。

本次前端需求的目标是建立两个稳定标识：

| 标识 | 作用 | 生命周期 | 存储位置 |
|---|---|---|---|
| `anonymous_id` | 标识当前浏览器中的匿名用户 | 长期保存，直到用户主动清理 | `localStorage` |
| `chat_session_id` | 标识一段具体聊天会话 | 可长期保存，也可被用户切换/新建 | `localStorage` |

二者关系：

```text
anonymous_id 1 -> N chat_session_id
```

也就是说，一个匿名用户可以创建多段聊天会话；每段聊天会话都能独立恢复历史消息。

## 二、目标

1. 前端首次进入页面时，能够初始化匿名用户标识。
2. 前端能够向后端创建或恢复聊天会话。
3. 用户再次打开页面时，能看到上一次聊天记录。
4. 用户发送消息时，前端必须携带 `anonymous_id` 与 `chat_session_id`。
5. 前端为后续“会话列表、多会话切换、登录后合并匿名会话”保留扩展点。

## 三、非目标

1. 本文档不定义后端数据库表结构。
2. 本文档不实现后端短期记忆注入逻辑。
3. 本阶段不要求跨设备同步，匿名会话仅在当前浏览器内稳定。
4. 本阶段不做浏览器指纹识别，只使用随机 ID。

## 四、核心用户流程

### 4.1 首次进入聊天页

```text
用户打开聊天页
  -> 前端读取 localStorage.anonymous_id
  -> 不存在则请求后端创建 anonymous_id，或由前端生成 UUID
  -> 前端保存 anonymous_id
  -> 前端读取 localStorage.chat_session_id
  -> 不存在则调用后端创建 chat session
  -> 前端保存 chat_session_id
  -> 拉取当前 chat_session_id 的历史消息
  -> 渲染聊天页面
```

推荐优先级：

1. 优先采用后端生成 `anonymous_id` 和 `chat_session_id`。
2. 如果后端接口暂未完成，前端可临时用 `crypto.randomUUID()` 生成本地 ID。

### 4.2 再次进入聊天页

```text
用户再次打开聊天页
  -> 前端读取 localStorage.anonymous_id
  -> 前端读取 localStorage.chat_session_id
  -> 调用历史消息接口
  -> 将历史 user / assistant 消息恢复到消息列表
```

### 4.3 发送聊天消息

```text
用户输入问题
  -> 前端校验当前是否存在 anonymous_id 和 chat_session_id
  -> POST /api/chat，携带 message、anonymous_id、chat_session_id
  -> 前端消费 SSE 流式事件
  -> delta 事件实时追加 assistant 文本
  -> done 事件后结束当前回复状态
```

请求体示例：

```json
{
  "anonymous_id": "anon_xxx",
  "chat_session_id": "chat_xxx",
  "message": "百万医疗险怎么选？"
}
```

### 4.4 新建一段聊天

```text
用户点击新建聊天
  -> 前端调用创建会话接口
  -> 后端返回新的 chat_session_id
  -> 前端更新 localStorage.chat_session_id
  -> 清空当前消息列表
  -> 进入新会话
```

## 五、本地存储设计

### 5.1 Storage Key

| Key | 示例值 | 说明 |
|---|---|---|
| `smartinsure_anonymous_id` | `anon_01HT...` | 匿名用户 ID |
| `smartinsure_current_chat_session_id` | `chat_01HT...` | 当前选中的会话 ID |
| `smartinsure_chat_session_cache` | JSON 字符串 | 可选，本地会话列表缓存 |

### 5.2 读写原则

1. 页面初始化时只读取一次本地 ID，然后进入会话初始化流程。
2. 后端返回新的 ID 后，前端立即覆盖本地存储。
3. 不在 localStorage 中保存完整聊天内容，完整消息以服务端为准。
4. 本地缓存只用于改善首屏体验，不作为最终数据来源。

## 六、前端模块拆分

| 模块 | 职责 |
|---|---|
| `anonymousIdentity` | 初始化、读取、保存 `anonymous_id` |
| `chatSession` | 创建会话、读取当前会话、切换会话 |
| `chatHistory` | 拉取历史消息并转换为前端消息模型 |
| `chatStream` | 发送聊天请求并消费 SSE |
| `chatStore` | 统一维护消息列表、流式状态、当前会话状态 |

建议文件组织：

```text
apps/frontend/
  src/
    lib/
      identity.ts
      chat-session.ts
      chat-history.ts
      chat-stream.ts
    stores/
      chat-store.ts
    app/
      page.tsx
```

如当前前端项目尚未采用该目录结构，可按现有结构等价落位。

## 七、页面状态设计

### 7.1 初始化状态

| 状态 | 含义 | UI 行为 |
|---|---|---|
| `initializing` | 正在初始化匿名 ID 和会话 ID | 输入框暂不可发送 |
| `loading_history` | 正在拉取历史消息 | 消息区显示加载状态 |
| `ready` | 会话就绪 | 可正常发送消息 |
| `streaming` | 正在接收 SSE 回复 | 禁止重复发送 |
| `error` | 初始化或请求失败 | 显示重试入口 |

### 7.2 消息模型

前端统一消息结构：

```ts
type ChatMessage = {
  id: string
  role: "user" | "assistant"
  content: string
  createdAt?: string
  metadata?: {
    products?: ProductCard[]
    sources?: SourceLink[]
    disclaimer?: string
  }
}
```

历史消息恢复时，后端返回的数据需要转换成该结构。

## 八、接口依赖

以下接口为前端期望依赖，最终路径可在后端设计时确认。

```http
POST /api/anonymous-identities
```

响应：

```json
{
  "anonymous_id": "anon_xxx"
}
```

### 8.2 创建聊天会话

```http
POST /api/chat/sessions
Content-Type: application/json

{
  "anonymous_id": "anon_xxx"
}
```

响应：

```json
{
  "chat_session_id": "chat_xxx",
  "title": "新会话",
  "created_at": "2026-05-22T10:00:00+08:00"
}
```

### 8.3 获取会话历史

```http
GET /api/chat/sessions/{chat_session_id}/messages?anonymous_id=anon_xxx
```

响应：

```json

  "chat_session_id": "chat_xxx",
  "messages": [
    {
      "id": "msg_xxx",
      "role": "user",
      "content": "百万医疗险怎么选？",
      "created_at": "2026-05-22T10:01:00+08:00"
    },
    {
      "id": "msg_yyy",
      "role": "assistant",
      "content": "选择百万医疗险时，建议重点看保障责任、免赔额、续保条件和健康告知。",
      "created_at": "2026-05-22T10:01:03+08:00",
      "metadata": {
        "products": [],
        "sources": []
      }
    }
  ]

```

### 8.4 聊天接口

```http
POST /api/chat
Content-Type: application/json

{
  "anonymous_id": "anon_xxx",
  "chat_session_id": "chat_xxx",
  "message": "百万医疗险怎么选？"
}
```

响应仍采用 SSE。

## 九、异常处理

| 场景 | 前端处理 |
|---|---|
| 本地无 `anonymous_id` | 创建匿名身份后继续初始化 |
| 本地有 `chat_session_id`，但后端返回 404 | 清除本地当前会话 ID，重新创建会话 |
| 历史消息加载失败 | 保留会话 ID，提示重试，不清空本地 ID |
| 聊天 SSE 中断 | 停止 streaming 状态，保留用户消息，提供重试 |
| 用户清理浏览器缓存 | 作为新匿名用户处理 |
| 多标签页同时打开 | 使用同一个 localStorage ID，当前阶段允许共享同一会话 |

## 十、安全与隐私要求

1. `anonymous_id` 不是登录凭证，不能当作强认证。
2. 前端不应展示完整内部错误栈。
3. 前端不应在 URL 中长期暴露 `anonymous_id`。
4. 清空会话时，应同时调用后端删除接口，并清理当前本地会话 ID。
5. 后续接入登录后，需要支持将匿名会话绑定到登录用户。

## 十一、验收标准

1. 首次进入页面时，前端能稳定获得并保存 `anonymous_id`。
2. 首次聊天前，前端能稳定获得并保存 `chat_session_id`。
3. 发送 `/api/chat` 时，请求体包含 `anonymous_id` 与 `chat_session_id`。
4. 刷新页面后，页面能自动拉取并展示上一次聊天记录。
5. 点击新建聊天后，会生成新的 `chat_session_id`，旧聊天记录不混入新会话。
6. 后端返回会话不存在时，前端能自动重建会话并恢复可用状态。
7. SSE 流式输出期间不会出现重复提交导致的消息错乱。

## 十三、测试建议

### 13.1 单元测试

1. `anonymous_id` 不存在时能创建并保存。
2. `anonymous_id` 已存在时不会重复创建。
3. `chat_session_id` 不存在时能创建新会话。
4. 历史消息接口返回值能转换成前端消息模型。

### 13.2 集成测试

1. 页面首次加载 -> 创建匿名身份 -> 创建会话 -> 加载空历史。
2. 用户发送消息 -> SSE 输出 -> 页面展示完整回复。
3. 刷新页面 -> 使用同一个会话 ID -> 恢复历史消息。
4. 新建聊天 -> 当前消息列表清空 -> 新消息进入新会话。

### 13.3 回归测试

1. 原有产品推荐卡片仍能展示。
2. 原有来源、免责声明、错误提示仍能展示。
3. 原有 SSE `delta`、`done`、`error` 事件解析不受影响。

## 十四、待后端确认项

1. `anonymous_id` 是否由后端生成。
2. `chat_session_id` 的接口路径与字段命名。
3. 历史消息接口是否支持分页。
4. assistant 消息中的产品卡片、来源、免责声明是否统一放到 `metadata`。
5. 会话不存在、归属校验失败时的状态码约定。
6. 删除会话、清空当前会话、新建会话的接口约定。
